# Security policy

## Supported versions

Only the code currently deployed from `main` receives security updates. Staging and feature branches are not production releases.

## Reporting a vulnerability

Do not open a public issue. Use GitHub private vulnerability reporting for this repository or contact the designated security owner privately. Include the affected route/component, reproduction steps, impact, and any suggested mitigation. Do not access, alter, or retain real user data while testing.

The security owner should acknowledge a report within two business days, triage severity, preserve evidence, rotate exposed credentials immediately, and coordinate disclosure only after affected deployments are remediated. Production secrets must never be pasted into issues, pull requests, logs, or chat.
